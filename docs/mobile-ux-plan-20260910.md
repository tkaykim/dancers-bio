# deetz 모바일 UI/UX 개선 계획

메시지 핫픽스를 먼저 적용한 뒤, 같은 레이아웃 문제가 여러 화면에서 반복되지 않도록 공통 화면 규칙부터 정리한다.
메시지 핫픽스 PR #233은 운영에 배포했고, 후속 1차로 지원자 시트의 모바일 폼을 수정했다.

## 2026-09-10 후속 1차 구현·검증

320px 지원자 시트에서 정산 저장 버튼이 카드 경계에 걸리고, 입력창은 14px 글자·36px 높이, 평가 버튼은 32px였음을 브라우저로 재현했다.
정산 입력창이 가용 폭 안에서 줄어들게 하고 글자는 16px, 입력창·저장·상태·평가·닫기 버튼은 44px 이상으로 맞췄다.
평가 점수는 5열로 배치하고 버튼 문구는 한 줄로 유지했다.
공통 시트는 동적 화면 높이, 모바일 여백, 안전 영역, 한국어 단어 단위 줄바꿈을 적용했다.
메시지 시트의 기존 전용 여백은 유지했다.

Chromium·WebKit에서 320·360·390·430px 및 844px 가로 화면의 지원자 폼 10개 검사가 통과했다.
기존 메시지 회귀 38개와 production build·TypeScript도 통과했다.
변경 파일 ESLint에서 `EvaluationPanel.tsx:35`의 기존 `react-hooks/set-state-in-effect` 오류 1개가 확인됐으며 해당 effect는 이번 변경 전 main과 동일하다.
동작 로직을 바꾸거나 린트 규칙을 끄지 않았다.
스크린샷·결과는 `Desktop/deliverables/deetz-mobile-layout-20260910/`에 있다.

2026-09-11 사용자가 PR #234의 커밋·푸시·운영 배포와 변경 안내 메일 발송을 승인했다.
은행 선택·캐스팅 프로필·단가·이력·거절 사유·운영 프로필의 실제 컴포넌트도 Chromium·WebKit에서 320·360·390·430px 및 844×390px 가로 화면으로 추가 검증했다.
공통 시트 60개 검사가 통과했고, 정산 저장 버튼의 행 경계와 모바일 폼 10개 검사도 재확인했다.
공통 시트의 가로 넘침·화면 높이·닫기와 은행 선택 동작을 검사했으며 저장·정산·거절 등 실제 업무 데이터는 변경하지 않았다.
다국어 작업과 분리된 작업 폴더에서 PR #234의 변경만 배포하며 번역·언어 선택 코드는 포함하지 않는다.
배포 결과는 PR #234의 production 상태와 공유 정본 `project_deetz_messaging.md`에 기록한다.
추가 검증 증거는 `Desktop/deliverables/deetz-mobile-layout-20260911/`에 저장했다.

다음 구현은 지원자 목록에서 프로필·대화·심사·다음 지원자로 이어지는 동선 정리다.

## 1. 공통 모바일 레이아웃 정리

현재 확인된 원인은 대화 화면의 고정 최소 높이, 하단 탭과 입력창의 중첩, 폭이 줄지 않는 flex 자식, 긴 제목과 버튼의 줄바꿈이다.
다른 화면도 같은 결함이 있다고 단정하지 않고 실제 사용자 흐름별로 재현 화면을 수집한다.

대상은 공고 상세·지원서·지원자 목록·프로필 시트·일반 프로필·메시지함이다.
320·360·390·430px와 가로 화면에서 긴 한국어·영문 활동명, 긴 URL, 여러 상태 배지, 로딩·오류·빈 상태를 함께 검사한다.

| 공통 요소 | 적용할 규칙 | 완료 기준 |
| --- | --- | --- |
| 페이지·시트 높이 | 스크롤 영역을 하나로 지정하고 키보드·안전 영역을 반영한다. | 입력과 주요 버튼이 화면 밖이나 탭 아래로 숨지 않는다. |
| 제목·본문 | 한국어는 단어 단위로 읽히게 하고 긴 영문·URL은 넘칠 때만 나눈다. | 가로 넘침이 없고 이름·핵심 조건을 확인할 방법이 있다. |
| 버튼·폼 | 버튼 문구는 한 줄로 유지하고 좁은 화면에서는 버튼 묶음을 세로로 배치한다. | 주요 터치 영역이 44px 이상이며 입력 글자는 16px 이상이다. |
| 목록·표 | 모바일에서는 필수 정보와 다음 행동을 먼저 보여준다. | 수평 스크롤 없이 지원자 확인·메시지·심사 행동을 수행한다. |

공통 컴포넌트 변경은 모든 사용처의 스크린샷을 비교한 뒤 반영한다.
전체 화면에 무조건 `break-all`이나 `overflow-hidden`을 적용해 내용을 숨기는 방식은 사용하지 않는다.

## 2. 지원자 심사 동선 개선

지원자 시트 상단에는 이름·현재 선발 단계·메시지 버튼을 두고, 포트폴리오·지원서 답변·평가·운영 정보의 순서를 정리한다.
심사 버튼은 화면 하단에서 접근할 수 있게 배치하되 위험도가 다른 `합격`·`미선발`·`최종 선발`은 상태와 효과를 구분한다.
다음·이전 지원자 이동, 필터·스크롤 위치 복원, 대화에서 프로필로 돌아오기를 함께 설계한다.

완료 기준은 `목록 → 프로필 → 대화 → 심사 → 다음 지원자`를 모바일 한 흐름으로 끝내는 것이다.
공동관리자와 채널 담당자는 실제 권한이 다른 만큼 보이는 행동과 서버 검사를 각각 검증한다.
선발 상태·동의·국적 공개·정산 권한의 기존 규칙은 해당 정본을 기준으로 유지한다.

## 3. 메시지함 탐색과 응답 관리

관리자는 프로젝트별 목록을 반복해서 열지 않고도 미답변을 찾을 수 있도록 운영 대화를 통합한다.
공동관리자에게는 담당 프로젝트만 보이며 이름·프로젝트 검색, 안읽음·미답변 필터를 제공한다.
안읽음은 열람 여부이고 미답변은 운영팀 응답 필요 여부이므로 두 상태를 구분한다.

우선 구현할 기능은 서버 검색·페이지네이션, 과거 대화 불러오기, 방별 작성 중인 내용 보존, 실패 메시지 수정·삭제, 저장된 답변이다.
현재 프로젝트 목록·인박스의 조회 상한과 N+1 조회를 함께 정리하고, 상한 밖의 오래된 미답변이 누락되지 않는 테스트를 추가한다.
공동관리자가 동시에 답장하는 상황에는 다른 운영자의 최신 응답을 알려 중복 발송을 줄인다.

실시간 전송 방식 변경은 초기 표시 시간·수신부터 화면 표시까지의 지연·폴링 요청량을 먼저 측정한 뒤 결정한다.
단체 대화방과 댄서 간 개인 DM은 이번 계획에 포함하지 않는다.

## 실행 순서와 승인 단위

| 순서 | 산출물 | 다음 단계로 넘어가는 조건 |
| --- | --- | --- |
| 메시지 핫픽스 | 프로필 진입·수신·재시도 수정 및 회귀 테스트 | 운영 적용 승인과 배포 후 주요 동선 확인 |
| 공통 레이아웃 | 재현 화면 목록·공통 컴포넌트 수정 | 주요 너비에서 넘침·가림 0건, 실제 기기 키보드 확인 |
| 지원자 심사 | 모바일 시안 1개와 실제 연결된 심사 흐름 | 관리자·공동관리자·채널 담당자의 역할별 업무 완료 |
| 메시지함 확장 | 통합 탐색·과거 대화·초안·미답변 관리 | 여러 프로젝트와 많은 대화에서 누락·권한 혼입 없음 |

진입 속도는 프로필에서 메시지 작성까지의 클릭 수와 대기 시간을 측정한다.
실패 여부는 단순 화면 정상 표시뿐 아니라 메시지 중복·누락·초안 손실과 실제 업무 완료 여부로 판정한다.
각 단계는 별도 변경으로 검토하고 운영 배포를 승인받는다.
