mydancersbio · Growth Engine

댄서·프로젝트 양방향 자동 채움 구현 계획

공급(댄서 프로필을 자동 수집·생성해 가입 전환)과 수요(프로젝트 공고 자동 수집·중개)를 동시에 채워 플랫폼을 활성화하는 성장 엔진. 아래는 확정된 전략과 단계별 구현 로드맵입니다.

📅 2026-05-31 상태: 전략 확정 · 구현 대기 SSOT: docs/growth-engine/PLAN.md
핵심 한 줄. 이건 "잡보드"가 아니라 모든 한국 댄서의 정본·랭킹된 프로필 레이어다. 그래서 가입제안 후크가 "빈 게시판에 가입하세요"가 아니라 "당신 포트폴리오를 이미 만들어 놨습니다 — claim하세요"가 된다. 그리고 미claim 댄서에게 도착한 캐스팅 제안이 가장 강력한 전환 후크 — 두 엔진을 묶는 톱니바퀴.

01 성장 플라이휠

① 큐레이션·자동 수집
IG 크롤 → 프로필 + 스코어 자동 생성 (가입 0명이어도 공급 인벤토리 증가)
↓
② 단독 가치 → claim
예쁜 랭킹 프로필은 그 자체로 공유 가치 → 링크 배포 → claim → 실유저
↓
③ 수요 발생
대표 본업(섭외) + claim한 프로/네트워크가 프로젝트 게시
↓
④ ⭐ 미claim 댄서로의 제안 = 최강 후크
"누군가 당신을 캐스팅하려 합니다 → 응답하려면 claim하세요" → ②로 회귀, 최고 전환율
↺
⑤ 플라이휠
claim↑ → 디렉토리 풍부 → 창작자 매력↑ → 수요↑ → 제안↑ → claim↑

비대칭: 공급은 공개 데이터로 cold 씨딩 가능, 수요는 대표 본업이 실수요라 사실상 해소됨. → 유일한 병목은 공급(댄서 claim 전환).

02 확정된 전략 결정

#결정구현 함의
D1스코어 완전 비공개정렬 순서에만 작동. 댄서는 점수 존재조차 모름 (인지 시 경력 부풀리기 편법). server-only.
D2하이브리드 공개 디폴트경력·예명·사진은 claim 전 공개. 이메일·연락처는 항상 가림(관리자만). 모든 미claim 프로필에 "내려주세요" 옵트아웃.
D3Apify → 이메일 + IG DM수집 후 정리 → claim 발송. 저볼륨·개인화. IG DM은 반자동(사람 발송).
D4founder-as-demand + 상시풀대표 본업이 실수요. 부족분은 "상시 섭외풀"(진실·탈락없음). 가짜 특정공고+전원탈락은 기각.
D5컨시어지 인력 보유직접 중개·현장출동 가능 → 첫 실거래를 사람이 생성.

03 두 파이프라인

🟣 공급 — IG 크롤 → 프로필 → 아웃리치 (3단계 큐)

A. 발견 풀 싸다·거대

팔로우그래프에서 핸들 + 싼 신호(팔로워수·72명과의 맞팔수·bio키워드) 대량 수집. dedup = IG 숫자 user_id(핸들 X).

B. 스크랩 큐 관리자 제어

자동 랭킹된 후보를 "며칠에 정밀 스크랩" 배정. 관리자가 보고 순서·날짜 수정. 하루 N개 throttle.

C. 검수 게이트 사람 승인

정밀 스크랩 → LLM 경력 추출(미검증 플래그) → 프로필 자동 생성 → 관리자 승인 → 디렉토리 공개.

아웃리치 → claim 전환

이메일/IG DM 발송 + 추적(조회·전환). claim 시 대기 중 제안 연결 → 실유저.

기각된 대안. "가짜 특정 공고 + 전원 탈락"은 좁은 신에서 승자가 한 명도 없는 패턴으로 들키고, 반복 탈락이 지원자 인게이지먼트를 태워 공급 전환을 거꾸로 깎는다. → 대신 상시 섭외풀(진실·탈락없음).

🔵 수요 — 프로젝트 자동 수집 검토·발행·중개 부분 이미 완성

크롤러 (신규)
댄서채용 정보 흩어진 소스 → Apify 스케줄 수집
↓
webhook 어댑터 (신규)
/api/ingest/project → 기존 createIngestionAction 재사용
↓
검토 → 발행 → 중개 (이미 있음)
project_ingestions + /admin/projects/import: LLM 파싱·중복탐지·발행·병합·기각 전부 동작 중

즉 수요 파이프라인은 새 검토 UI를 만들 필요 없이 자동 수집(크롤러+webhook)만 붙이면 된다.

05 리스크 · 가드레일 (협상 불가)

  • 🇰🇷 PIPA — 대량 자동생성 프로필이라 "내려주세요" 옵트아웃 + 연락처 마스킹이 필수 선제. 옵트아웃 요청률을 건강도 지표로.
  • IG ToS / 밴 — Apify 크롤·팔로우그래프는 ToS 위반 → managed proxy·저볼륨·소스계정 분리. IG DM 매스 발송 금지(반자동).
  • 미검증 경력 공개 — LLM 추출 경력은 unverified 플래그 + 보수적 추출, claim 시 본인 수정.
  • 나무위키 — 보조 소스로 좋음(유명 댄서 일부). CC BY-NC-SA·유저편집 → 정본 아님, 교차참조·출처표기.
  • 가짜 특정공고 금지 — 모든 프로젝트는 진짜 결과(승자/풀 등록)로 이어져야.
