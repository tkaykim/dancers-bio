# 메시지 핫픽스 · 2026-09-10

지원자 프로필과 일반 댄서 프로필에서 대화를 열고, 같은 프로젝트 대화로 돌아올 수 있도록 연결했다.
사용자 승인 후 PR #233을 병합했고, `www.deetz.kr` 운영 배포와 로그인 동선 검증을 완료했다.

## 변경된 사용 흐름

| 진입 화면 | 변경 후 행동 |
| --- | --- |
| 지원자 보기 → 프로필 바텀시트 | 상단의 `메시지 보내기`로 대화를 열고, 닫으면 심사 중이던 프로필로 돌아온다. |
| 일반 댄서 프로필 | 관리자·프로젝트 소유자·공동관리자가 관리할 수 있는 프로젝트를 선택해 대화를 시작한다. |
| 메시지 메뉴 | `운영 메시지함`에서 담당 프로젝트의 대화로 이동한다. |
| 프로젝트 메시지함 | 전체 대화를 기본으로 보여주며 미답변 필터를 별도로 제공한다. |
| 댄서 메시지함 | 지원 전 운영팀이 먼저 보낸 연락도 수신하고 답장한다. |

대화는 기존 `(project_id, dancer_id)` 방을 재사용한다.
일반 프로필에서 대화를 시작해도 지원서를 만들거나 선발 상태를 바꾸지 않는다.
프로젝트 운영 권한은 매 요청마다 서버의 `can_manage_project`로 다시 확인한다.
계정에 연결되지 않은 프로필은 수신할 수 없다는 안내를 표시한다.
비공개 프로젝트의 새 수신자에게는 접근이 허용된 대화의 프로젝트 제목·상태만 보완하며, 공고의 다른 비공개 필드는 전달하지 않는다.

## 모바일·전송 수정

- 화면과 키보드 높이에 맞춰 대화 영역을 조정하고, 대화 중에는 공통 하단 탭이 입력창을 가리지 않게 했다.
- 긴 링크·활동명·프로젝트명은 화면 안에서 줄바꿈하며, 보내기 버튼은 줄이 갈라지지 않는다.
- 입력창은 여러 줄로 늘어나고 모바일 Enter는 줄바꿈으로 동작한다.
- 데스크톱 Enter 전송은 한글 조합 중 입력을 제외하고, Shift+Enter는 줄바꿈으로 유지한다.
- 전송 실패 메시지를 화면에 보존하고 동일한 멱등키로 재시도한다.
- 전송 중 새로 작성한 내용은 실패 처리 때문에 덮어쓰지 않는다.
- 발신 성공으로 수신 커서를 앞당기지 않아, 그 사이 도착한 상대 메시지도 조회한다.
- 과거 메시지를 읽는 중에는 새 수신 때문에 화면을 강제로 내리지 않고 `새 메시지 보기`를 표시한다.
- 대화 불러오기 실패에는 뒤로 가기와 재시도 경로를 제공한다.

## 검증과 한계

최종 확인: 서버·정책 테스트 16개와 Chromium·WebKit 브라우저 검증 38개가 통과했다.
변경 파일 ESLint·TypeScript·프로덕션 빌드도 통과했다.

`node --test scripts/messaging-hotfix.test.cjs`는 서버 진입·권한 거절·미가입·삭제 프로젝트·멤버 연결 실패·프로젝트 선택 범위를 검증한다.
`npx tsx --test src/lib/messaging/messaging.test.ts`는 기존 메시지 정책 회귀를 검증한다.
`scripts/qa-messaging-hotfix.cjs`는 실제 React 컴포넌트를 번들하고 외부 요청과 서버 액션만 테스트 응답으로 대체한다.
Chromium·WebKit에서 320·390·768·1440px의 대화·일반 프로필·실제 지원자 시트·운영 메시지함, 양방향 입력, 실패 복구와 동시 수신을 확인한다.
스크린샷과 실행 결과는 `Desktop/deliverables/deetz-messaging-hotfix-20260910/`에 저장한다.

배포 전 운영 DB의 기존 비공개 QA 대화를 SELECT로 검사했다.
공동관리자는 담당 방 1개와 메시지를 조회했고, 댄서는 자신의 방 1개만 조회했으며 다른 댄서 방과 내부 메모는 0개였다.
무관계정의 운영 권한은 false이고 해당 방·메시지 조회 결과는 모두 0개였다.

브라우저 검증은 테스트 응답을 사용하므로 실제 고객 발송·외부 알림 도착을 검증했다는 뜻은 아니다.
키보드 처리는 VisualViewport와 짧은 화면으로 검사했으며 실제 iPhone·Android 기기의 소프트 키보드 검수는 배포 전후 별도로 확인한다.
스키마와 운영 환경변수는 변경하지 않았다.
배포 후 로그인 검증에서 기존 QA 방의 멤버 연결·읽음 처리는 실행됐으며 고객 메시지와 외부 알림은 발송하지 않았다.
