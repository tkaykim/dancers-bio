# 지원자 관리 모바일 UI/UX 재구성

## 재현한 문제

320px 화면에서 프로젝트 제목 옆의 관리 버튼이 제목을 한두 글자씩 줄바꿈하게 만들었다.
지원자 목록도 체크박스·사진·이름·태그·심사 버튼을 한 줄에 배치해 이름과 채널 정보가 세로로 길게 밀렸다.
검색 입력창은 정렬·필터 버튼 때문에 넘쳤고, 선발 단계 이름과 인원이 여러 줄로 갈라졌다.
긴 프로필 이름은 시트 헤더와 본문에 반복됐으며 메시지 버튼이 프로필 정보보다 위에서 전체 폭을 차지했다.
긴 포트폴리오 파일명과 오른쪽 열기 문구는 같은 폭을 두고 경쟁했다.
운영 도구를 실제로 펼친 검사에서는 참가 포기 링크의 복사 버튼이 화면을 3px 넘었다.

## 변경한 구성

| 영역 | 변경 |
| --- | --- |
| 페이지 제목 | 프로젝트 제목에 전체 폭을 주고 공고·업로드·메시지 링크를 다음 줄로 분리했다. |
| 선발 단계 | 단계 이름과 인원을 한 줄로 유지하며 가로 스크롤로 탐색한다. |
| 검색·필터 | 모바일에서는 검색을 전체 폭으로 배치하고 정렬·필터를 다음 줄에 둔다. |
| 지원자 카드 | 정보와 심사 버튼을 위아래로 분리하고 현재 단계를 모바일에서도 표시한다. |
| 선택 도구 | 체크박스의 조작 영역을 넓히고 선택 개수·일괄 처리 버튼이 좁은 폭에서 자연스럽게 다음 줄로 이동한다. |
| 프로필 시트 | 헤더를 `지원자 프로필`로 고정하고 전체 이름은 본문에서 읽는다. |
| 프로필 연락 | 프로필 정보 아래에 메시지와 전체 프로필 링크를 나란히 둔다. |
| 심사 | 현재 단계와 다음 단계·거절 버튼을 시트 하단에 고정한다. |
| 상태 되돌리기 | 자주 쓰지 않는 상태 변경은 본문의 `선발 상태 변경`에서 펼친다. |
| 거절 사유 | 사유 입력과 취소·확정 버튼을 분리하고 취소하면 보던 프로필로 돌아간다. |
| 평가 | 44px 터치 영역을 유지하면서 점수 버튼 묶음의 최대 폭을 제한했다. |
| 운영 도구 | 모바일에서는 공지·일정·정산·공동관리자 도구를 접어서 제공하고 PC에서는 사이드바를 유지한다. |
| 링크 복사 | 참가 포기 링크 입력창에 최소 폭 해제를 적용해 복사 버튼을 화면 안에 둔다. |

심사 버튼은 기존 `advanceRound`와 서버 액션을 재사용한다.
최종 확정 확인·정원 안내·결과 발송 경로를 새로 만들거나 우회하지 않는다.
채널 담당자처럼 심사 권한이 없는 사용자는 심사·메시지·정산 입력을 사용할 수 없다.
다국어 세션의 번역 파일과 작업 폴더는 변경하지 않는다.

## 적용 기준과 검증

W3C의 [320 CSS px 리플로 기준](https://www.w3.org/WAI/WCAG21/Understanding/reflow)과 [터치 대상 최소 크기](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum), Google의 [관련 정보와 행동을 함께 묶는 구성 원칙](https://developer.android.com/design/ui/mobile/guides/components/material-overview)을 참고했다.
이 화면에서는 보조 버튼에 40px, 주요 심사·폼 버튼에 44px 조작 영역을 사용한다.
화면마다 버튼을 무조건 크게 늘리지 않으며 전체 WCAG 준수 인증을 의미하지 않는다.

Chromium·WebKit에서 320·360·390·430·844·1280px의 목록·필터·선택·빈 상태·시트·단계 이동·취소·읽기 전용 흐름 36개를 검증했다.
공통 바텀시트 6종은 5개 너비와 두 브라우저에서 60개, 메시지 회귀는 38개 검사를 통과했다.
프로덕션 빌드와 TypeScript가 통과했다.
변경 파일 ESLint는 기존 `EvaluationPanel.tsx:35`, `RejectReasonDialog.tsx:28`의 set-state-in-effect 오류 2개를 제외한 파일에서 통과했다.
두 effect는 변경 전 main과 동일하며 규칙을 끄거나 동작을 바꾸지 않았다.

실제 QA 계정으로 프로덕션 빌드를 실행해 지원자 페이지·운영 도구·기존 대화·프로필 진입을 확인한다.
실제 고객 메시지·선발·정산 데이터는 변경하지 않으며 기존 QA 방의 멤버 연결·읽음 처리만 발생한다.
실제 iPhone·Android 소프트 키보드는 별도 기기 검수 범위다.
스크린샷·실행 결과는 `Desktop/deliverables/deetz-applicant-ux-20260911/`에 저장한다.
운영 배포 식별자와 결과는 공유 정본 `project_deetz_messaging.md`에 기록한다.
